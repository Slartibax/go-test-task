# go-test-task


## Запуск

1. Скопировать `.env.example` в `.env`. Оба compose-файла и процесс берут настройки оттуда. Одноимённая переменная окружения процесса перекрывает значение из файла.
2. `make local-up` - для локального композа, `make dev-up` - для дев композа
3. Если не менялась переменная  `DEPLOYMENT_PROXY_PORT` то обращаться к api - http://localhost:8000
4. Остановить `make local-down` - для локального композа, `make dev-down` - для дев композа

Кошелек создается при первом депозите.

## Переменные `.env`

| Переменная | Кто читает | Назначение |
| --- | --- | --- |
| `APP_NAME` | никто | Подпись проекта в файле. Сервис и compose её не используют. |
| `APP_ENV` | никто | Подпись окружения в файле. Сервис и compose её не используют. |
| `HTTP_ADDR` | приложение | Адрес HTTP-сервера внутри контейнера. Пустое значение становится `:8080`. Caddy ходит на `app:8080`, поэтому порт в этом адресе должен оставаться `8080`. |
| `DB_HOST` | приложение | Хост Postgres. В compose это имя сервиса `database`. |
| `DB_PORT` | приложение | Порт Postgres внутри сети compose, обычно `5432`. |
| `DB_DATABASE` | приложение и compose | Имя базы. Compose передаёт его в `POSTGRES_DB` и в проверку `pg_isready`. |
| `DB_USERNAME` | приложение и compose | Пользователь базы. Compose передаёт его в `POSTGRES_USER` и в проверку `pg_isready`. |
| `DB_PASSWORD` | приложение и compose | Пароль базы. Compose передаёт его в `POSTGRES_PASSWORD`. Для уже созданного тома Postgres пароль повторно не применяется. |
| `DB_MAX_CONNS` | приложение | Верхняя граница пула соединений. Пустое значение — `40`. Число должно быть больше нуля. |
| `DB_MIN_CONNS` | приложение | Сколько соединений пул держит открытыми. Пустое значение — `10`. Не больше `DB_MAX_CONNS`. |
| `DEPLOYMENT_PROXY_PORT` | compose | Порт Caddy на хосте. Пустое значение в шаблоне порта — `8000`. |
| `DEPLOYMENT_PGSQL_PORT` | локальный compose | Порт Postgres на хосте. Пустое значение в шаблоне порта — `5432`. Dev-compose этот порт не публикует. |

Соединение с базой открывается с `sslmode=disable`. Соединение пула живёт не дольше 30 минут и простаивает не дольше 5. Эти два срока в `.env` не вынесены.

## Тесты

```bash
make test
make test-integration
```

# Что бы я поменял
1. API сделать REST-овым
2. Делать не изменения кошелька POST запросом, а создавать новую транзакцию в отдельной группе /transactions
3. Сами транзакции делать не с одной АПИ группы, а по типам /withdraw-transactions и /deposit-transaction - чтобы не бренчить логику в одном обработчике
4. Глобально бы вынес все что связано с сериализацией и дессерриализацией
5. Добавить базовую глобальную структуру ответа
6. Добавить глобальный хендлер ошибок в апи, чтобы не повторяться в каждом месте, и иметь единую точку логирования
7. С postgres использовал бы pgbouncer
8. Вместо синхронного изменения данных кошелька - делал бы это в фоне, потому-что в реальной жизни синхронных пополнений обычно не может быть + это бы сняло синхронную нагрузку на базу. А для надежности использовал бы posgres river
9. Можно еще сделать InMemory Batching
10. Структуру проекта подтянуть
11. Redis кеш с ивалидацией по транзакции кошелька
